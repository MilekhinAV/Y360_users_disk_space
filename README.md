# Статистика места на Дисках пользователей Яндекс 360

Скрипт `disk_space.py` выгружает в CSV занятое, свободное и общее место на личных Дисках сотрудников организации. Пользователь определяется по email и UID.

## Требования

- Python 3.9 или новее.
- Доступ к `cloud-api.yandex.net` и `oauth.yandex.ru` по HTTPS.
- OAuth-токен администратора для чтения списка сотрудников.
- Сервисное приложение, подключённое к организации для доступа к Дискам пользователей.

Используется только стандартная библиотека Python. Устанавливать зависимости через `pip` не требуется.

## Подготовка доступа

В скрипте используются два отдельных набора реквизитов:

| Настройка | Назначение |
| --- | --- |
| `ADMIN_TOKEN` | Получение списка сотрудников организации. Требуется разрешение `directory:read_users` и доступ к организации |
| `CLIENT_ID` и `CLIENT_SECRET` | Получение временного OAuth-токена каждого сотрудника через сервисное приложение |

### Токен администратора

В OAuth-приложении, через которое выпускается `ADMIN_TOKEN`, добавьте разрешение `directory:read_users`. Получите токен под администратором нужной организации.

Если права OAuth-приложения изменились, получите новый токен: ранее выданный токен автоматически новые права не получает.

### Сервисное приложение

В организации должна быть активирована функция сервисных приложений, а `CLIENT_ID` — зарегистрирован в списке сервисных приложений этой организации. Одного создания приложения на OAuth-сервере недостаточно.

Для чтения информации об объёме Диска настройте право `cloud_api:disk.info`. `CLIENT_ID` и `CLIENT_SECRET` должны принадлежать одному приложению. Права сервисного приложения на Диск не заменяют разрешение `directory:read_users` у `ADMIN_TOKEN`.

Подключение описано в [инструкции Яндекса по сервисным приложениям](https://yandex.ru/support/yandex-360/business/admin/ru/security-service-applications).

При настройке через метод [«Создать список приложений»](https://yandex.ru/dev/api360/doc/ru/ref/ServiceApplicationsService/ServiceApplicationsService_Create) учитывайте: запрос заменяет весь список. Для сохранения других приложений их тоже нужно включить в массив `applications`. Токен для управления этим списком требует права `ya360_security:service_applications_write`; для повседневного запуска скрипта это право не требуется.

## Настройка `.env`

Создайте файл `.env` рядом с `disk_space.py`:

```text
project/
├── disk_space.py
└── .env
```

Заполните его своими реквизитами:

```dotenv
ORGID=8269182
ADMIN_TOKEN=your_admin_token
CLIENT_ID=your_service_app_client_id
CLIENT_SECRET=your_service_app_client_secret
```

| Переменная | Описание |
| --- | --- |
| `ORGID` | Числовой ID организации |
| `ADMIN_TOKEN` | Полный OAuth-токен администратора |
| `CLIENT_ID` | Полный ClientID сервисного приложения |
| `CLIENT_SECRET` | Полный Client secret того же сервисного приложения |

Правила файла:

- Имя — именно `.env`, без расширения `.txt`.
- Кодировка — UTF-8; BOM поддерживается.
- Каждая настройка находится на отдельной строке, без `\` в конце.
- Значения можно заключать в одинарные или двойные кавычки.
- Пустые строки и строки комментариев, начинающиеся с `#`, разрешены.
- Комментарии после значения, многострочные значения, escape-последовательности и подстановки `${...}` не поддерживаются.
- В реквизитах не должно быть кириллицы, пробелов внутри значения и невидимых символов. Заглушки из примера нужно заменить реальными значениями.

`.env` ищется в папке скрипта независимо от текущей папки запуска. Настройки также можно передать через переменные окружения. **Окружение имеет приоритет над `.env`**, даже если переменная окружения содержит пустую строку.

Если в терминале остались старые настройки, для использования `.env` в Bash/Zsh выполните:

```bash
unset ORGID ADMIN_TOKEN CLIENT_ID CLIENT_SECRET
```

Не добавляйте `.env` в Git и не публикуйте его содержимое. При использовании Git добавьте `.env` в `.gitignore`.

## Запуск

Из папки скрипта:

```bash
python3 disk_space.py --output disk_space.csv
```

С указанием папки результата и числа потоков:

```bash
python3 disk_space.py --output results/disk_space.csv --workers 3
```

Без параметров:

```bash
python3 disk_space.py
```

В этом случае файл получает имя `disk_space_YYYYMMDD_HHMMSS.csv` по локальному времени компьютера.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--output` | `disk_space_YYYYMMDD_HHMMSS.csv` | Путь к CSV |
| `--workers` | `5` | Число параллельно обрабатываемых пользователей; целое число больше нуля |
| `--help` | — | Справка по запуску |

Относительный путь результата отсчитывается от текущей папки терминала. Недостающие папки создаются автоматически. Существующий файл не перезаписывается: для следующего запуска укажите новое имя.

После завершения скрипт выводит путь к файлу, число обработанных пользователей и число ошибок.

## Формат CSV

Кодировка — UTF-8 с BOM, разделитель — точка с запятой (`;`), десятичный разделитель — точка. Одна строка соответствует одному уникальному UID.

| Столбец | Содержимое |
| --- | --- |
| `email` | Основной email сотрудника |
| `uid` | Идентификатор пользователя |
| `is_enabled` | Состояние аккаунта из списка сотрудников: `True` / `False`; пусто, если API не передал поле |
| `used_bytes` | Занятое место в байтах |
| `free_bytes` | Свободное место в байтах |
| `total_bytes` | Общий объём Диска в байтах |
| `used_gib` | Занятое место в GiB |
| `free_gib` | Свободное место в GiB |
| `total_gib` | Общий объём Диска в GiB |
| `status` | `ok` — данные получены; `error` — запрос пользователя завершился ошибкой |
| `error` | Этап и код ошибки; при успехе пусто |

Объёмы рассчитываются так:

```text
free_bytes = max(total_bytes - used_bytes, 0)
1 GiB = 1024³ байт
```

Значения в байтах сохраняются без округления, значения в GiB — с четырьмя знаками после точки. Корзина отдельно из свободного места не вычитается. При превышении квоты свободное место равно нулю.

При ошибке пользователь остаётся в CSV, а поля объёмов остаются пустыми. **Пустое значение не означает нулевое потребление.** Для расчётов используйте строки с `status=ok`, а строки с ошибками проверяйте отдельно.

При импорте в Excel задайте столбцу `uid` тип «Текст», чтобы сохранить длинные идентификаторы без округления. Для дробных столбцов выберите десятичный разделитель «точка».

## Как выполняется выгрузка

1. Скрипт получает полный список сотрудников страницами по 100 записей и убирает повторные UID.
2. Для каждого сотрудника получает временный токен через OAuth token exchange.
3. Запрашивает информацию о его Диске и записывает результат в CSV.

Запросы выполняются и для отключённых аккаунтов, но скрипт не меняет их состояние и не разблокирует их. Получение данных для таких аккаунтов не гарантируется; отказ записывается в `error`.

Ошибка отдельного пользователя не останавливает обработку остальных. Если не удалось получить полный список сотрудников, выгрузка останавливается до создания CSV. При прерывании процесса после начала записи файл может содержать только часть результатов.

Для HTTP 429, 500, 502, 503, 504 и обрабатываемых сетевых сбоев предусмотрено до пяти попыток. Базовые паузы между попытками — 1, 2, 4 и 8 секунд. Числовой `Retry-After` учитывается с ограничением 300 секунд. Таймаут сетевых операций — 60 секунд; это не общий лимит времени выгрузки.

Отчёт отражает личные Диски пользователей, а не общие диски или общий пул хранения организации. Данные собираются в течение запуска и не являются моментальным снимком на одну дату и секунду.

## Диагностика ошибок

Место появления ошибки помогает определить этап сбоя:

| Ошибка | Что проверить |
| --- | --- |
| `Не заданы в окружении или .env: ...` | Наличие `.env` рядом со скриптом, имена переменных и заполненность значений |
| Сообщение о печатных ASCII-символах | Кириллицу, пробелы и невидимые символы в указанном параметре |
| `Ошибка API: http_403. Выгрузка не завершена` в консоли | `ADMIN_TOKEN`, его доступ к организации и право `directory:read_users`; при изменении прав выпустите новый токен |
| `oauth:http_400:invalid_request` в CSV | Параметры обмена токена, подключение сервисного приложения и аккаунт пользователя. Этот код сам по себе не устанавливает точную причину |
| `oauth:http_400:invalid_client` в CSV | Соответствие и актуальность `CLIENT_ID` / `CLIENT_SECRET` |
| `oauth:http_403:...` в CSV | Доступ сервисного приложения к получению токена указанного пользователя |
| `disk:http_403` в CSV | Права временного токена на Диск, настройки сервисного приложения и состояние аккаунта |
| `oauth:network_error` или `disk:network_error` | Сеть, DNS, прокси и доступность API |
| `invalid_json` | Ответ не удалось разобрать как JSON; возможен ответ промежуточного сервера или прокси |
| `Файл уже существует` | Выберите новое имя через `--output` |

Для OAuth в CSV выводится только поле `error`, проверенное по фиксированному списку известных кодов. Например:

```text
oauth:http_400:invalid_client
```

Неизвестный код, некорректное тело ответа или ответ больше 16 KiB обозначается `unavailable_error_code`. Это отметка скрипта об ограниченной диагностике, а не код OAuth-сервера. HTTP-статус сохраняется.

Скрипт не выводит токены, секреты, `error_description`, HTTP-заголовки и полное тело ошибки. Для разбора проблемы достаточно передать код ошибки и указать, возникает ли она у всех пользователей или только у части.

## Коды завершения

| Код | Значение |
| --- | --- |
| `0` | Выгрузка завершена без ошибок пользователей |
| `1` | Есть ошибки пользователей либо выгрузка не завершена из-за обрабатываемой ошибки API или файла |
| `2` | Ошибка параметров запуска или настроек |

Принудительное завершение процесса может иметь другой код. Наличие CSV само по себе не подтверждает завершение выгрузки.

Если рядом со скриптом находится `test_disk_space.py`, запустите:

```bash
python3 -m unittest -v
```

Тесты используют подставные ответы и тестовые реквизиты; реальные запросы к организации не выполняются.
